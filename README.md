# Finance Tracker

Mobile-first застосунок для особистого обліку фінансів (стиль iOS 26 Liquid Glass у власних кольорах: графіт + смарагд): доходи, витрати, перекази, рахунки, категорії, бюджети, борги, фінансові цілі, історія та аналітика.
Це статичний сайт для GitHub Pages. Дані зберігаються в `localStorage`, працює офлайн як PWA.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # unit-тести шару розрахунків, демо-даних та імпорту
npm run build      # production-збірка в dist/
npm run preview
```

## Деплой на GitHub Pages

1. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Push у `main` запускає `.github/workflows/deploy.yml`: тести → збірка → публікація.

`base: './'` + `HashRouter`, тому застосунок працює з будь-якого підшляху (`https://<user>.github.io/<repo>/`),
а оновлення сторінки на будь-якому екрані не дає 404.

## Навігація і тексти

- На телефоні 4 вкладки: **Головна, Аналітика, Борги, Профіль** + кругла кнопка «+». Категорії, бюджети, цілі, історія, рахунки й налаштування відкриваються з «Профілю» (на комп'ютері всі розділи в боковому меню).
- Текст ніде не обрізається «…»: назви переносяться, великі суми зменшують шрифт (`components/ui/FitText.tsx`), вузькі картки перебудовуються в рядки (container queries). Перевірено на 320–1440 px з довгими назвами й сумами до 9 876 543,21 ₴.

## Архітектура

```
src/
  types/                 доменні моделі (Transaction, Category, Budget, Debt, Goal, Account, Settings)
  services/
    storage/             storage layer: async-адаптер (localStorage → легко замінити на Firebase),
                         репозиторії колекцій, валідація імпорту, експорт
    calculations/        усі фінансові розрахунки (баланс, доходи/витрати, бюджети, борги, цілі, аналітика)
  store/                 FinanceContext (стан + дії, синхронізація похідних полів), UIContext (toasts, confirm)
  hooks/                 useFinance, useFinanceStats, useTheme, useUI …
  components/            ui/ common/ layout/ dashboard/ transactions/ categories/ budgets/ debts/ goals/ analytics/
  pages/                 екрани (secondary — lazy-loaded)
  layouts/               AppLayout: sidebar (desktop) / bottom navigation + FAB (mobile)
  data/                  дефолтні категорії/рахунки, генератор демо-даних
  utils/                 форматування валюти/дат, id
```

UI-компоненти не звертаються до `localStorage` і не рахують фінансові показники самі — лише через
`services/storage` і `services/calculations`. Щоб перейти на Firebase, реалізуй `StorageAdapter`
(`read/write/remove`) і виклич `setAdapter()` під час старту застосунку.

## Бізнес-логіка

- **Баланс** = початкові баланси рахунків + доходи − витрати ± повернення боргів. Перекази між рахунками змінюють лише баланси рахунків, не загальний.
- **Борги** не впливають на баланс при створенні. Кожне повернення («Додати повернення» / «Погасити все») — окрема операція `debt_repayment`: отримав гроші → баланс зростає, повернув → зменшується. Повернення не рахуються як доходи/витрати у статистиці. Залишок і статус боргу (Активний / Очікує / Прострочено / Погашено) рахуються з операцій.
- **Бюджети**: загальний місячний або для категорії; період — щомісяця або власний. 80% → попередження, >100% → «Перевищено бюджет».
- **Категорії**: видалення категорії з операціями переводить її в «Архівовану» — історія не втрачається. Категорію можна приховати з вибору.
- **Цілі**: накопичення/зняття з історією, відсоток, залишок, дедлайн, скільки відкладати щомісяця.
- Порівняння з минулим періодом у поточному місяці/тижні/році робиться за той самий проміжок часу (1–7 жовтня vs 1–7 вересня).
- Дати зберігаються як локальний ISO (`2026-10-01T14:32:00`), у UI — `1 жовтня 2026`. Суми — `24 580 ₴`.

## Експорт / імпорт

Налаштування → Експорт даних (JSON з transactions, categories, budgets, debts, goals, accounts, settings).
Імпорт перевіряє структуру файлу, показує, що в ньому, і перед заміною просить підтвердження.
